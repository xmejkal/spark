## New findings

A. fix, "Value proven by". The repository eval cannot show a difference. The library has about 10 parts and 3 boards, at most 3 per verb (sense 1, drive 1, indicate 1, sound 2, compute 3). The gate gives both matchers the same set, so both land 100% in the top 5. Library records have no `about` or `tags`, so the 0.8 and 0.4 weights never run. Fix: use a fixture drawer with 10 or more same-verb offers that carry about and tags. Count rank 1 and "shown", score `matcher.rank` on Offers alone, and add the precision cases from 15.

B. fix, the callers. The gate blocks the next strategy. candidates() drops offers of another verb (needs.py:178, 191) before a matcher sees them. So "relaxing the gate is a new subclass" is false. Fix: give the base class `admits(need, offer)` (default: same verb) and pass every Offer to it. Compute the costly `said` (`owes`, `broken`, `validate`) only for admitted offers.

C. fix, the Matcher API. A score per pair blocks batch matchers. The 6.2 row is `match(needs)`, and its "later" is embeddings. Fix: callers call only `rank(need, offers)`, which a subclass can override. `score` is a helper.

D. fix, the data. `about`, `description` and `tags` reach Claude as prose from vendor-page research, shared records and imports. §6.4.6 (a label is stripped, capped, never obeyed: drawer.py CONTROL, LABEL_MAX) does not cover them. Fix: strip and cap them when a record or entry is written. idea.md says describe text is data, never an instruction.

E. fix, "The problem". A wrong claim about today's code. The 8-cut (parts.py:2017-2018) replaces `need["candidates"]` before paging, so the JSON loses the parts too, not only the text. The "score above 0" rule must change that cut, and under WordOverlap the JSON grows (see 11).

F. suggest, `--matcher`. SameWords and WordOverlap need a verb, which `--need` lacks. NameContains ignores the verb on `--match`. Fix: each class names the callers it serves, and `--matcher` refuses a misfit.

## Finding 9: both sides

- Move: "simple and small". The classes, the two old rules, the fields, `describe` and parity make a working first version, and A shows the eval cannot prove WordOverlap today.
- Keep: the PO called matching "one of the most important parts". A Strategy with no second scoring class proves no extensibility and leaves score, why and the threshold (2, 6, 11) untested.
- Middle: keep WordOverlap as a small second class, and move the eval tool and the PO's case file to P206, where `about` and `tags` first exist.
