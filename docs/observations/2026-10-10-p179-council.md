The change: a live `check_vendor_pins.py` wrote the vendor header it fetched into spark's own
`.spark/cache/`, because P10's read fallback was also its write target, and nothing said where it
wrote ([#124](https://github.com/xmejkal/spark/issues/124); found in P100's round 0 on 2026-10-09).

tech lead and the documentation expert on the first commit, then the refuter on the branch with
the council's fixes. All ran on Opus. Their full reports were kept in the session's scratch folder;
this file is the record, and each finding is a row in [`INDEX.md`](INDEX.md) (N1–N28).

Ids: PA (PO assistant), U (user), TL (tech lead), DOC (documentation), B and Q (the refuter's
attempts to break it, and its code-quality reading). Severity as the reviewer gave it: fix (before
the merge) or suggest (a later card). Every row that says what was done went in with PR [#125](https://github.com/xmejkal/spark/pull/125), merged 2026-10-10; a row that says raised did not.
