### electronics-firmware:physics

The item changes no power, current, heat or radio use. Those rows do not apply, and I did not research them.

- PHYS-1 · One serial port serves one program, by a lock, and the lock is taken by the tools spark runs and not by every tool on the Mac. mpremote 1.29.0 opens with `exclusive=True` (installed transport_serial.py:52, :64-65), and its failure text is `failed to access <device>` (:104). That text is raised for any OSError on open when `wait == 0`, so it does not say the port was busy (a missing port gives the same text). esptool 5.5.0 opens with `serial_for_url(port, exclusive=True, do_not_open=True)` (installed esptool/loader.py:455-457). spark's own `ConsoleProbe` script sets `s.exclusive = True`, and exits with 3 (`EXIT_PORT_BUSY`) when the errno is EAGAIN or EWOULDBLOCK (board_console.py:35-53). `box.py log` opens `serial.Serial(found, 115200, timeout=0.2)` with no `exclusive` (the pixel-games worktree, tools/box.py:437): pyserial 3.5's default is no lock, so that console read neither waits for a held port nor makes others wait. · E · the files named · provenance: stated (source code of the installed versions; pyserial's default from board_console.py:36-37's note and my reading of the call, not from pyserial's source, which I did not open) · supports only: a hold that records "in use" cannot rely on the OS lock to stop box.py's console; a failed open of a busy port shows as mpremote's `failed to access <port>` or as esptool's exception text, which spark classes as `board_not_read` with esptool's own line (board_look.py:223-239).

- Q-T2 · May a hold by another project stop a touch (a new P892 stop), or does it only print a line and let the touch go on? · It decides whether Cut 2 changes `KnownBoardService.judge` (FEAS-8, DIR-1) or only the view and the check command.
- Q-T3 · May a tool write a hold without the person's yes, or does a hold need the person's yes as a grant does? · It decides whether the hold is its own record with a different trust level from the grant (FEAS-7), and whether a relayed write is allowed.
- Q-T4 · How long may a hold last, and does it renew? · It decides what a dead session costs (FEAS-11) and whether the grant's 1440-minute cap is the model. C11 asks for 60 to 90 minutes.
- Q-T5 · The word: "hold", "claim" or another, given that "grant" and "kept board" exist? · It decides the script and Operation names (DIR-3).
- Q-T6 · Is Cut 1 (the view alone) enough for now, with Cut 2 waiting on a second project that keeps the same board in the PO's real store? · It decides whether anything is built beyond the view (DIR-4).
- Q-T7 · Is a spark command that `box.py` calls by an absolute path acceptable to the pixel-games project, given that its plugin is 0.4.0 and a change inside pixel-games' own tools is out of scope in the brief? · It decides whether the "tool that is not spark's" job (★C6) is met by a command alone or needs a change on their side (FEAS-10).
