## The first test, proposed: the runtime spike
Proposed 2026-11-15 by the synthesis, from council/feasibility.md:72 (FE-38) and council/risks.md:27-28 (the risks lens's A1 and A2; its A2 is A11 in this file). Kind: research spike (settles feasibility only). It needs the PO's yes to publish (brief Q4) and his pass lines at Q1. The page holds no spark data and no home path.

1. Publish a throwaway page from Claude Code with `publish_files`, then `declare_capabilities` with `db` and `user`. A click writes a row. Does `db_get` read it at Claude's next turn, and after how long? (A1)
2. Claude writes a row with `db_write`. Does the open page show it through `onSnapshot` with no reload? (A1)
3. Republish the page. Are the rows still there? (A2)
4. Publish the same page with the built-in Artifact tool that commands/build.md:161 names. Do both routes reach the same artifact and the same `db`? (A2)
5. Declare `files` with the session's project id, if one is known. Does the page list the project's files? (A8)
6. Close the Claude Code session. Click on the page, then open a session. Does `db_get` read the row, and what did the page show while no session was open? (A11; council/risks.md:28)
7. Only if brief Q9 keeps an MCP route: does `host:<name>` reach a local stdio server in the PO's desktop app? (council/feasibility.md:11, FE-1)

If brief Q32 says yes, one more step on the same page: declare `room`, and see whether the publishing Claude Code session is admitted (kind "agent"). The runtime says "plus your publishing session when admitted" and "NOTHING persists and messages can drop" (`describe_capabilities room`, contract 0.2.96, read 2026-11-15).

Pass line, proposed 2026-11-15: steps 1 to 3 and 6 pass 3 of 3 tries each (A1, A2, A11); steps 4 and 5 record what was seen, pass or not; nothing else is published. Run 2026-11-15 (steps 1 to 3) and 2026-11-16 (step 6): see Results.
