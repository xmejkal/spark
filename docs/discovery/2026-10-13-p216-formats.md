# P216 step 4: where each AI tool reads its files

The card: [P216, #197](https://github.com/xmejkal/spark/issues/197). Researched 2026-10-13, from the makers' own docs.

## The short version

The row "instructions: `AGENTS.md`" is mostly right, with two changes. Gemini CLI does not read `AGENTS.md` by
default. It needs the setting `context.fileName`. Claude Code reads `AGENTS.md` natively now (from v2.1.277), but a
`CLAUDE.md` or `CLAUDE.local.md` above the working folder stops it. The `@AGENTS.md` import stays the safe way. The
skills row is right: all five tools read `SKILL.md` folders, and all except Claude Code also read `.agents/skills/`.
The agents row is right: there is no shared format. Each tool has its own folder, and Copilot also reads
`.claude/agents`. The private-rules row is right: there is no shared format, and only Claude Code has a local file in
the project.

## What this changes for steps 5 and 6

Step 5 stays as planned. `CLAUDE.md` holds `@AGENTS.md`, so Claude Code loads `AGENTS.md` by the import. Step 6 must
also write `CLAUDE.local.md`, and that is safe only because `CLAUDE.md` exists: a `CLAUDE.local.md` alone stops Claude
Code from reading `AGENTS.md` [1]. Init must tell Gemini CLI users to add `AGENTS.md` to `context.fileName`, or
init can write that one setting for them. Spark's skills can stay in `.claude/skills/` for Claude Code and also go to
`.agents/skills/` for the four other tools.
