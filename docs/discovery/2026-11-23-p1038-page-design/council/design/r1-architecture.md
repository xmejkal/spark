# Round 1, the architecture lens (Opus), on the architect's draft (5e99b392)

2026-11-23. Read-only. The lens checked every file:line that the draft cites, the P1035 plan (its PR 2 and round 2), the core-gaps finding, tests/test_architecture.py and patterns-and-names.md, and searched for each new name.

Summary: the seam is sound. One Value, `FlowReading`, is read by `show --json` and by the page. The core stays free of the flow area. The design builds on P1035 PR 2 without designing it again, and only `write_page` changes. One must-fix: the published stamp in `.spark/page.json` always reports `behind: true`. Four claims are wrong or out of date: A6, A10, A12 and A15.

## Findings

- A1 · must-fix · The published stamp turns itself stale. The stamp test puts every file whose change changes the page's bytes into `STAMP_FILES`. The `read` value in `.spark/page.json` changes the bytes, so the test forces `.spark/page.json` into `STAMP_FILES`. `flow.py page --published` then writes that file after the publish, and `published.behind` stays true (`PublishedPageStore.write`, write_flow_page.py:85-88). Fix: `STAMP_FILES` and its test get a named exclusion list of spark's own page records (`.spark/page.json`, `.spark/page-request.json`). The published record takes the stamp and fingerprint from `data-written` and `data-fingerprint` of the published `page.html` and writes no page again (`WriteFlowPage.run` always calls `write_page`, write_flow_page.py:197). Better: record them in the same call as the `--artifact` id (page.md:37-44) and drop the extra flag.
- A2 · should-fix · `reading_of` is a fourth way to read the flow, beside `phases_of`, `flow_and_guide` and `read_flow` (show_flow.py:80-95). `read_flow` has no caller in production code, only tests and docstrings. Fix: `reading_of` calls `flow_and_guide` and `fingerprint_of`. `ShowFlow.run` and `write_page` both move to `reading_of`. `read_flow` becomes a one-line projection of `reading_of` for the tests. `RunRequest` keeps `phases_of` and `fingerprint_of` (run_request.py:154, :167), so the click path does not change.
- A3 · should-fix · The second D22 test ("fails when `write_page` reads a project fact that is not in `FlowReading`") cannot be written as described. Fix: hold the rule by construction. Split `write_page` into a pure `page_of(reading, parts)` and the write. The project's name (write_flow_page.py:148) goes into `FlowReading`.
- A4 · should-fix · `masked_page` masks `FlowPage` one field at a time (write_flow_page.py:123-129), so each new text is one more field to forget. Fix: `FlowPage` holds the reading as plain values (`reading.to_dict()`), and one `privacy.masked(...)` call covers all of it, as `PageWiring` does (flow_page.py:30-34). `to_dict()` keeps `stands_at` (show_flow.py:112).
- A5 · should-fix · `DrawnFrom` clashes with `drawn_from`, a field of `sheet.WriteResult` (sheet.py:401-404) and a JSON key (kept_files.py:273). Fix: rename it, for example `NamedBuild`, in its own module or in `flow_reading.py`.
- A6 · should-fix · `--read` clashes: `parts.py --read` reads a document (run_cost.py:37-38, datasheets.py:204). The line "no file holds any of them" is wrong: `drawn_from`, `--read` and `decided` (init_project.py:47) exist. Fix: rename the flag, for example `--shared-as VALUE` or `--audience VALUE`, and correct the line.
- A7 · should-fix · "Stamp" has a second meaning: `needs_basis.stamp_of` returns sha256 values of the brief (needs_basis.py:33-37). Fix: keep `FlowStamp`, call the page.json entry "the published record", and note the `needs_basis` use.
- A8 · should-fix · `DecidedLine` has no writer of its origin. `decided` enters `.spark/project.json` through `init_project.py --answers` as a list of strings (init_project.py:46-49). Without a change there every line reads "origin not recorded", so D15 is not met. Fix: story 1b lets `--answers` accept `{line, by, at}`, takes `at` from the clock, and Claude passes `by`.
- A9 · should-fix · The spark version comes from the bench area (board_facts.py:21, :29), against the direction of the areas. `records.board_records.PLUGIN_ROOT` exists and a test checks it (test_architecture.py:560-566). Fix: one `spark_version()` in records beside `PLUGIN_ROOT`, used by `board_facts` too. `BuildRecordStore` takes it as an injected reader, as it does `clock` (build_record.py:59-61).
- A10 · should-fix · "`FlowFollowUp.refresh` is the one place that knows the page changed" is false. The kept build (`write_kept_page`, write_flow_page.py:158-163) and `flow.py page` also write the page. The fault table's "written only at /spark:page" is wrong for the same reason (page.md:10). Fix: the "page changed" fact is the `Written` answer of `write_page`, or `FlowStamp.newest`. A later event comes from the core's seam after any writing run.
- A11 · should-fix · The live-page seam does not fit the PO's streaming words. A `Reporter` is a strategy for one run (events.py:40), not a subscription that LangGraph, a web page and an SSE MCP can hold. Only Claude's MCP writes the Artifact database. Fix: the core emits a "project written" event with the project and `FlowStamp.newest`, and each consumer adapts it. The page's adapter writes to the database only through a session that holds the Artifact tools. Build none of it now.
