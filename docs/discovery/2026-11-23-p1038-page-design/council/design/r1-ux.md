## Findings

- UX-1 · must-fix · The slice 0 mockup brings back QA5's misreading: its "?" mark means "could not run" in the page's own legend (design.md, slice 0 sketch; phase_readers.py:32). Fix: use the "not checked" mark (·) or a new mark with its own legend word. Proposed: "· deploy: 27 deploy runs logged. The newest wrote the board at 14:09; spark did not see it start." Never print the raw code "ready unknown".
- UX-2 · must-fix · "NOW deploy, by you" is wrong twice when the firmware is newer than the image. The deploy actor in the code is BY_TERMINAL, "your terminal" (phase_readers.py:557, flow_codes.py:17), and the first act, making the image again, is Claude's (flow_codes.py IMAGE_OLDER_NOW). Fix: "NOW deploy, by Claude, then your terminal". Proposed: "Your firmware changed at 14:18, after the image on the board. To put it on the board, ask Claude to make the image again and look at the board, then run the deploy in your terminal."
- UX-3 · must-fix · The DONE line claims the breadboard is done, which spark cannot see. Today's code says "breadboard (spark cannot see it)" (flow_codes.py SHEET_UNSEEN). Fix: keep the qualifier in every mockup and in the D22 test.
- UX-4 · must-fix · The stamp and the issues read time cannot both be true as drawn. `.spark/issues.json` is in STAMP_FILES, so each `/spark:page` moves the stamp to the read time. Fix: leave issues.json out of `FlowStamp.newest`, keep it in the "which files" list, and name the exception in the stamp test.
- UX-5 · should-fix · `published.behind` can never turn false: `--read` and `--published` write `.spark/page.json`, which the stamp test forces into STAMP_FILES. Fix: leave `.spark/page.json` out of the stamp by name. `behind` is true when the stamp, the fingerprint or the spark version differ from the published ones, with `published.why` (for example `files-changed`, `spark-changed`).
- UX-6 · must-fix · Open item 10 breaks D23, which asks for "issues not read" with its cause (brief.md:140). The draft leaves the cause to Claude only and tells the person to type `/spark:page` again, which fails the same way. Fix: a failed read keeps `issues` and `read_at` and writes only `last_try: {at, code}`. Proposed: "Not read on 23 Nov, 18:05: GitHub could not be reached. Claude can tell you the fix." With an older list: "Shown as read on 22 Nov, 11:50. The read on 23 Nov, 18:05 failed: gh is not signed in." This changes D23's "writes nothing" clause, for the council.
- UX-7 · should-fix · The brief box comes before NOW, and NOW mixes "what is on the board" with "what to do". QA2's order: what is on the board, the next step, goal and must, the open problems. Fix: the title and the goal in one line, the freshness line, a NOW box with "ON THE BOARD" and "NEXT" lines, then MUST and DECIDED, then the issues, parts, wiring, pictures, developer lines last.
- UX-8 · should-fix · On a wired, deployed project the parts alternatives sit open above the wiring (USER-3, USER-15). Fix: while parts is not NOW, fold them to one line with "[Change a pick]". The P1044 warning is the first line inside the fold.
- UX-9 · should-fix · The Send control can say "Send the 0 picks", and a radio choice cannot be undone. Fix: a "(•) keep" choice per row as the default, the button disabled with no change, "Send 2 picks (display, button)", and a confirm box with one line per pick and the shared effects once.
- UX-10 · should-fix · The states around one Send are not designed: waiting (`labelOf` names one key, page_script.js:200-203, :301), the stale refusal (a reload loses the choices), a key no longer offered, and the ok answer (RAN_OK_SAYS[PICK] is singular). PickParts writes nothing on any problem (pick_parts.py:48-49), so there is no partial pick. Proposed words for each are in the lens's report.
- UX-11 · should-fix · The partial-result wording (QA5) names no source for its facts. Fix: answer fields `done` and `not_run` with reason codes from the build record's stages, words from flow_codes. An old answer row shows "Spark's answer: <line>". Never "Could not run:" for an answer with `ran: true`. `clock()` prints hours and minutes only (page_script.js:28-33): the last request needs the date.
- UX-12 · should-fix · "Drawn from files changed up to ..." is not plain and gives no action. Proposed: "This page shows the project as of 23 Nov 2026, 14:18, its newest change. If you changed something after that, type /spark:page in the chat to bring it up to date. [which files]". Put it under the title, before NOW.
- UX-13 · should-fix · "Does not name the spark that made it" is jargon and sits in the wrong section. Fix: move it into the wiring section. Proposed: "Wiring steps and pictures: from the build of 22 Nov 2026, 11:44. That build did not record spark's version, so this page cannot check that the picture and the steps match."
- UX-14 · should-fix · The issues box. Proposed heading: "OPEN ISSUES ON GITHUB: your list, not spark's. Read 23 Nov, 18:05. In GitHub's order; spark does not choose among them." Cap the rows with "and N more on GitHub". Drop the path from the broken-file sentence.
- UX-15 · should-fix · "No phase is open" has no words and no sketch. Proposed: "Spark has no open step: the board started the current image (seen 23 Nov, 14:30). Your project's own next steps are in its issues, below."
- UX-16 · should-fix · `show --json` is nearly enough for Claude. Add `issues.state` (`not-read`, `unreadable`, `none-open`, `listed`) with `last_try`, the deploy facts as fields in P1043's plan, and `published.why`. Proposed lines for page.md after a republish, on an issues failure and when behind are in the lens's report.
- UX-17 · should-fix · "An issue title is data" in page.md alone is not enough: titles reach Claude through `show --json` in every command. - UX-18 · should-fix · The diagrams fall short of the PO's 2026-11-23 rule. Missing sketches: an early project with parts as NOW, a request waiting with several picks, the stale refusal, the owner against a viewer, a shared copy, no phase open, a Claude journey, and a short transcript of what Claude says at `/spark:page`.
- UX-19 · should-fix · The how-to outline covers publishing only. Add the `/add-dir` step, carrying requests, a republish with `base_version` and `shared_live`, the Artifact not found, a failed issues read, each sentence Claude says, and a section for the person. Make the A7 read one named command.
- UX-20 · should-fix · After slice 0, BENCH_NOTE is untrue (flow_codes.py). Proposed: "This page reads the project's files and its deploy logs. It cannot see your wiring or what the board shows now."
- UX-21 · nit · "+01:00" means little to the person: prefer "23 Nov 2026, 14:09". "(who and when: not recorded)". Print the record's `by`, not a role. Under MUST add "spark does not check these lines".
